## A. 实际修改

- P0：客户日志改为 `rotate -1`，保留期由独立维护器按接收日期统一执行；不按 30 份轮转淘汰。不删除活跃 `.log`，已打开归档跳过；兼容历史 `.gz`/日期/数字后缀。
- 存储保护：每 30 秒统计 syslog 和总空闲；警告时记录 STORAGE_PRESSURE，临界时暂停本项目 receiver，保留近期证据。具备恢复阈值、暂停标记和启动检查。磁盘完全满时即使写标记失败也尝试停止写入。
- 写入性能：默认 `sync=off / flushOnTXEnd=on / asyncWriting=off`；可选 durability `sync=on`。主队列与 receiver CPU/内存/线程有界。
- 可观测性：`GET /syslog`、`netblackbox syslog-status`、expected_sources；轻量 impstats + 当前日志有界 tail + receiver 自身错误日志。来源 SILENT 不被判为 DOWN。
- 验收：保留 Level 1，新增外部 sender/check 和管理员手工设备测试；唯一 marker、真实 source/time/content/duplicates；范围未覆盖或扫描不完整时 NOT_TESTED。
- benchmark：必须显式隔离、loopback、fixture PID 匹配；报告发送与文件可见速率，不伪造 ingress 数、逐条 fsync 延迟或物理持久条数。
- Agent：后台维护失败隔离；I/O/SQLite 操作错误回滚重试，健康状态降级；快照完成标记避免完成但未确认的任务重复采集，部分证据保留；HTTP API 改为固定单处理线程并保留 socket timeout。
- 安装器：新增字段自动补齐，旧配置先备份，升级期间停止旧轮转单元，异常恢复服务；不改已有数据目录，不做数据库 schema migration。

## C. 设计决策

详细依据与官方 rsyslog 文档链接见 [SYSLOG-DESIGN.md](SYSLOG-DESIGN.md)。

1. 选择日期+大小轮转，客户日志 `rotate -1`，Python 仅清理过期、未打开归档。文件名接收日期决定保留，不以 mtime 代替时间语义。多留一天兼容旧文件时区。
2. 不许在空间不足时静默删近期日志；以暂停新接收保护已有证据。抽样阈值不是硬配额，峰值流量/其他软件仍可在间隔内填盘；强隔离需 quota/独立卷，不能虚构绝对容量保证。
3. Direct action 保留错误反馈，无额外磁盘队列；固定主队列承接批量。performance 降低同步成本，durability 更严格但仍受虚拟磁盘和宿主缓存影响。
4. UNKNOWN/RECEIVING/SILENT 属于来源观测；RECEIVER_ERROR 必须有服务、监听或写入异常证据。接收器健康不能证明外部链路正常。
5. `action.failed` 在真实 Debian 上并不覆盖所有 dynafile 错误。因此完整 write_failure_count 为 null，另显示原始 action_failure_count 和明确错误证据；不会伪称精确统计。写入错误锁存到 receiver 明确 resumed 或进程重启，避免因错误窗口过期假恢复。

## F. 兼容性

旧 JSON 无需手工补齐新字段即可 load/render/install；原参数、syslog 地址/端口、CIDR、data_dir 保留。syslog_rotate 字段为兼容保留，已经不再代表保留期。原始配置由 manifest 的 before/ 逐文件备份。

SQLite schema 不变，user_version 保持原值，无新增破坏性迁移。原 metrics/events/incident 可读；新增 observer 元数据独立存入 `state/syslog-observer.json`（version 1），不回填虚假的历史 source 总数。既有日志和归档不重写、不清空；升级可能按正常保留策略清理已过期归档，保留期内证据不会因升级而提前删除。

## G. 代码质量审查结论

| 项目 | 已核实/处理 | 边界 |
|---|---|---|
| Agent/receiver 异常恢复 | Restart=always；Agent watchdog；受控暂停有 marker/恢复阈值 | 完全满盘时启动阶段仍可能失败，不能保证继续持久采集 |
| SQLite WAL/事务 | FULL、已提交数据异常进程退出可读；操作失败 rollback/retry | 未测物理掉电；存储损坏需外部备份 |
| incident 跨重启 | active ID/排队任务持久化，boot 变化重置去抖但保留事件 | 空窗期间精确恢复时刻不可知 |
| snapshot 调度 | complete 标记避免重复；未完成目录保留后重试；DB ack commit 后释放 future | 进程死亡前未完成的采集只能补采，不能还原原时刻 |
| 磁盘压力 | syslog 独立 guard 不依赖 Agent；未知占用保守暂停 | 30秒采样不是 quota；exports/部署备份仍由管理员管理 |
| 轮转/HUP | 统一锁、真实 FD 检查、归档不再被 writer 重开、真实轮转回归 | 不支持管理员绕过 lock 同时运行 logrotate |
| 安装/回滚 | 原配置备份；停止旧 timer 后替换；记录服务变化便于失败回滚 | APT 包变更不自动降级 |
| 卸载 | 只移除管理的程序/配置，证据数据保留 | 需管理员保存当前源码才能方便回滚 |
| 资源界限 | 固定消息队列/最大消息长度/receiver 资源限制；统计尾读/来源上限；API 固定线程；inventory 时间预算 | 手工 exports 和历史安装备份需外部容量管理 |
| 并发/异常 | 清理独占锁；SQLite 单主写线程/后台独立连接；maintenance failure 不逃逸主循环 | 同时运行多个安装器仍应由维护窗口约束，不支持多管理员并行升级 |

下一阶段 PVE 方案见 [PVE-ROADMAP.md](PVE-ROADMAP.md)，本轮没有部署任何 PVE 功能。
